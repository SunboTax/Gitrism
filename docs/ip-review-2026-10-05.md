# Preliminary intellectual property review

Review date: October 5, 2026, Asia/Shanghai.

Reviewed implementation: Gitrism 0.1.0, commit `8908cbe05c4d151a25cc5bc3c4816767d5b85cc2` and its existing VSIX. Documentation added by this review is subsequent to that release.

This is a preliminary engineering and public-record review, not a legal opinion or a completed freedom-to-operate analysis. The scoped checks identified no direct copying of another product's packaged assets or runtime dependency on GitLens. A relevant Axosoft patent was found and compared with the implementation; the comparison identified material differences. Worldwide trademark, figurative-mark, design, patent-family, and equivalents analysis remains incomplete.

## Distribution status

The authenticated GitHub repository query and public repository search both reported `SunboTax/Gitrism` as **public** on the review date. Earlier descriptions of the repository as private must not be used to assess current exposure. Public code and release distribution are part of this review's context. This review did not change repository visibility.

The Wordmark interface treats complex input differently from the field-tag search interface. An initial combined-name query using `OR` returned literal `OR` marks, and an initial multi-phrase slogan query returned broad individual-word results. The accessible name searches do not establish that the name or slogan can be registered or used in every country. Pending and unindexed filings, phonetic equivalents, translations, unregistered rights, related goods and services, and other similar marks may matter. Software in class 9 and software services in class 42 are relevant areas for a complete search; this review does not treat those classes as the only potentially relevant ones.

## Patent search and implementation comparison

Google Patents assignee queries produced these usable results:

- `assignee=GitKraken`: zero returned results. The separate Axosoft result below shows why searching only the product's current brand would be insufficient.
- `assignee=Axosoft`: one returned grouped result, **US11868765B2**, titled *Automatically presenting a visualization of information within a terminal*, assigned to Axosoft, LLC. Priority date: July 12, 2021. Grant date: January 9, 2024.

The search response characterized the US record as active. This is secondary database information; official assignment, maintenance-fee, legal-status, prosecution, and family records were not independently verified. A grouped search result is not an exhaustive count of publications or family members.

Sources: [Google Patents record](https://patents.google.com/patent/US11868765B2/en), [retrieved patent PDF](https://patentimages.storage.googleapis.com/10/75/fb/57022ce6894815/US11868765.pdf). The record page was blocked, but the public PDF was retrieved successfully. Its scanned claims were read visually on PDF pages 20–21, printed columns 13–16; plain-text extraction did not produce usable text.

### Independent claims 1, 18, and 20

| Claimed feature, paraphrased | Observed Gitrism implementation |
| --- | --- |
| Receive an operation input at a terminal command line interface | Extension commands and Webview controls initiate operations; `GitService.run` starts a background Git process with Node's `execFile`. No Gitrism terminal command line interface was found |
| Identify and execute the operation and produce its output | Gitrism invokes Git operations. This isolated overlap is not a comparison against a complete claim |
| Display output in the command line interface and automatically display an interactive visualization in a visualization pane, both within the terminal | Gitrism renders its workspace in a VS Code Webview, opens native diff editors, and shows errors in the Webview or extension UI. It does not provide the claimed combination of a terminal command line interface and visualization pane within that terminal |
| For independent claims 18 and 20, receive a change-directory operation through that terminal interface and display the resulting directory and visualization there | Repository selection uses the extension's repository picker and built-in `vscode.git` API. No such Gitrism change-directory terminal workflow was found |

Dependent claims mention Git, log graphs, diffs, blame, and visual interactive rebase, but retain the requirements of their underlying independent claim. Those feature names alone do not establish a match. The checked code showed no Gitrism use of terminal creation, terminal input handling, or terminal shell execution APIs.

The current implementation appears to lack the stated terminal/command-line arrangement of these independent claims. This is an implementation observation, **not** a legal non-infringement opinion. Claim construction, equivalents, indirect liability, other claims in related patents, and territorial applicability were not resolved.

Broader searches for GitLens, GitKraken in full text, Syntevo, Fournova, Sublime HQ, version-control graph visualization, and interactive rebase returned Google Patents HTTP 503 access blocks. The CNIPA patent query entry returned HTTP 412. Those attempts yielded no usable search results and cannot exclude patents held by other vendors or unrelated owners. This review is therefore not a patent clearance search for every implemented workflow.

## Interface and asset comparison

The visual references were the [official GitLens product page](https://gitkraken.com/gitlens) and its commit-graph/composing-changes screenshots, the [Git Graph public demo](https://github.com/mhutchie/vscode-git-graph), and the [Git History public demo](https://github.com/DonJayamanne/gitHistoryVSCode). These are samples of published interfaces, not an exhaustive review of their current or historical screens. Gitrism's graph reference was its existing browser-test screenshot using synthetic repository data; its other views were also checked in the Webview source.

| Reference | Shared conventions | Observed differences |
| --- | --- | --- |
| GitLens | Commit lanes, branch labels, search, author/date information, file inspection | Gitrism uses its own brand and a row of nine task tabs, separate filter controls, a fixed adjacent commit-details pane, initial-letter avatars, and a file-list/commit-form working view. The sampled GitLens interface uses an icon navigation rail, different graph controls and labels, graphical author/status indicators, and a composing-changes sheet |
| Git Graph | A graph beside commit metadata and native diffs | The sampled Git Graph interface uses a branch filter and checkbox toolbar and expands details inside a selected graph row. Gitrism places details beside the table and exposes other workflows through its own tabs |
| Git History | Searchable history, references, author information | The sampled Git History interface places metadata beneath commit messages and branch/tag actions along the right of each item. Gitrism uses dedicated table columns and an adjacent details pane |

These observations support differentiation in the sampled overall layouts. They do not decide whether a particular protected expression is substantially similar, or whether trade dress or registered design rights exist. Common Git terminology, graph lines, and VS Code theme colors should not be treated as exclusive to one product, but independently writing code is not by itself a complete defense to every type of IP claim.

Exact-file SHA-256 comparison found no matches between current Gitrism resource files and the selected installed reference assets: GitLens 19.3.0 (175 asset files), GitLens 18.3.0 (180), and Git History 0.6.20 (26). The comparison covered SVG/raster images, CSS, and font formats in those installations. A whole-file hash check cannot detect modified copies, partial copying, equivalent rendering, or code similarity. No comprehensive source-to-source comparison with other products was performed.

Reference images and patent scans were retained outside the repository as review evidence; none was added as a Gitrism product asset or to its VSIX.

## Implementation, licenses, and provenance

The existing 0.1.0 VSIX contained 21 entries. Its JavaScript imports were this project's modules, Node built-ins, and the host `vscode` module. It contained no `node_modules` directory or third-party runtime library. Its compiled modules and resources matched the corresponding local files exactly before this review's documentation edits. The lockfile's 138 dependency packages were marked as development dependencies.

Installed GitLens 19.3.0's `LICENSE.txt` applies MIT terms except to files in or under a directory named `plus`; `LICENSE.plus` imposes separate subscription and redistribution restrictions. The audit does not regard GitLens Pro as MIT-licensed. No Gitrism runtime dependency on GitLens or use of its subscription validation was found. Gitrism's own MIT license does not authorize another party's code or remove any third-party obligations.

The pre-release `history.bundle` passed `git bundle verify` and contains complete historical refs. Its main history has 14 commits from the initial MVP on October 4, 2026, through the last pre-upgrade committed presentation change. A separate workspace snapshot preserves the later pre-rename implementation. Current `graphLayout.js`, `workspace.css`, and `timeline.css` match that snapshot exactly. The snapshot, existing VSIX, and reviewed files were hashed for this audit.

Important provenance limits:

- Most later feature work was preserved as a workspace snapshot, not as one historical commit for each implementation step.
- The published initial-release root commit records the resulting code, not its entire development process.
- Commit timestamps and this audit's hashes are supporting evidence, not independent proof of authorship, originality, or legal ownership.
- Prior development notes state that the local GitLens manifest's commands and workflow categories were referenced. That account and this review do not establish a formal clean-room process.
- This review did not inspect proprietary GitLens implementation source or reuse competitor code. It used local license/manifest information, reference asset hashes, public screenshots, and public patent material.

## Assessment and remaining work

The scoped copying, dependency, brand-presentation, and sampled interface checks did not identify a concrete reason to remove a current feature or asset. The found Axosoft patent warrants retaining this comparison and reviewing it again if terminal integration is added. The current findings do not justify declaring the project free of infringement risk.

A complete assessment would still require accessible searches of the relevant national trademark registers, near-name and figurative-mark analysis, applicable design registrations, a broader patent search with family and official status checks, and professional claim analysis where needed. Public distribution increases the importance of those gaps. Private or personal use is not a general exemption; independent development does not by itself eliminate patent risk, and a non-affiliation statement does not cure a confusing mark.

The accompanying [evidence index](ip-review-evidence-2026-10-05.json) records search outcomes, retrieved-source hashes, and the implementation baseline. The full local evidence archive includes raw responses, browser captures, external references, and provenance hashes. No published release tag, commit history, or binary was replaced by this review.
